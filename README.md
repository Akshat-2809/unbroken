# Unbroken — unbrokenops.com

Production site for Unbroken: an AI-native enterprise platform for logistics and supply chain, currently in stealth. It's a faithful port of the approved homepage design plus a real "Talk to Rajat" form. It's built the same way as Class of One.

Everything lives in one Next.js 16 app in [`web/`](web/). The form is handled by a **Server Action** in the same app, so there is no separate API service. It writes to Postgres (Neon) and sends emails through Resend.

## Local setup

Requirements: Node 20.9 or later, and a Postgres database.

```bash
cd web
npm install
cp .env.example .env.local      # then fill in the values
npm run db:migrate              # creates the talk_requests table
npm run dev                     # http://localhost:3000
```

Postgres for local work, pick one:

- **Docker:** `docker run --name unbroken-pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=unbroken -p 5432:5432 -d postgres:17`. This matches the default `DATABASE_URL` in `.env.example`.
- **Neon:** create a free project and use a dev branch's connection string.

If `RESEND_API_KEY` is empty, the form still works and the emails are skipped with a log line.

## Environment variables

| Variable | Required | Notes |
|---|---|---|
| `DATABASE_URL` | yes | Postgres connection string. Use Neon's **pooled** URL on Vercel. Without it, the form shows an error asking people to email instead. |
| `IP_HASH_SALT` | yes in production | Random string (`openssl rand -hex 32`). IPs are stored only as salted hashes, for rate limiting. |
| `RESEND_API_KEY` | for email | From resend.com → API Keys. |
| `EMAIL_FROM` | for email | `Unbroken <hello@unbrokenops.com>`. The domain must be verified in Resend. |
| `NOTIFY_EMAIL` | for email | Inbox that receives each new request. |
| `NEXT_PUBLIC_SITE_URL` | no | Defaults to `https://unbrokenops.com`. Used for canonical URLs, sitemap and OG tags. |

## How the "Talk to Rajat" form works

1. The form posts to the `startTalk` Server Action (`src/app/actions/talk.ts`) with `useActionState`: name, work email, area ("I work in") and the honeypot `website`.
2. If the honeypot is filled, the action returns a normal-looking success and stores nothing.
3. zod validates the input. The email is trimmed and lowercased. The area must be one of the four listed.
4. Rate limit: 10 per IP per hour, counted in Postgres (indexed on `ip_hash, created_at`). This works across serverless instances.
5. The row goes into `talk_requests`: `id, name, email, area, created_at, ip_hash, user_agent`. Email is unique. A duplicate is treated as success, with no error and no second email.
6. Both emails are sent with `after()`, once the response has gone out: the acknowledgement ("Thanks. Rajat will be in touch.") and the notification to `NOTIFY_EMAIL`, with reply-to set to the sender. An email failure is logged and never fails the request.
7. UI states: idle → submitting (button disabled + spinner, screen-reader announcement) → success (the design's "Received" card) or error (next to each field, keeping what the person typed).

The email box in the footer stores nothing. It carries the address to this form and moves the cursor to Name (`src/lib/talk/draft.ts`).

## Deploy to Vercel

1. Push the repo to GitHub, GitLab or Bitbucket, then in Vercel choose **Add New → Project** and import it.
2. Set **Root Directory** to `web`. The framework preset (Next.js) and the build command are detected automatically.
3. **Database:** Project → **Storage** → **Create Database** → **Neon (Postgres)**, and connect it to the project. This adds `DATABASE_URL` to the environments you choose.
4. Add `IP_HASH_SALT`, `RESEND_API_KEY`, `EMAIL_FROM` and `NOTIFY_EMAIL` under Settings → Environment Variables, for Production (and Preview if you want previews to send emails).
5. Run the migration once against the production database, from your machine:
   ```bash
   cd web
   DATABASE_URL="<Neon connection string from Vercel>" npm run db:migrate
   ```
   Repeat this whenever you add a migration.
6. Deploy. Preview deployments serve a `Disallow: /` robots.txt, so they stay out of search results.

## Connect the domain

1. In Vercel: Project → **Settings → Domains** → add `unbrokenops.com`, then `www.unbrokenops.com`, and choose to **redirect `www` to the apex**.
2. Vercel shows the exact DNS records to create (typically an **A** record for `@` and a **CNAME** for `www`). Add them at your domain registrar, removing any default "Parked" records first.
3. Wait for both domains to show **Valid Configuration**. HTTPS certificates are issued automatically.

To send email: in Resend, **Domains → Add Domain** → `unbrokenops.com`, add the DNS records it lists, click **Verify**, and set `EMAIL_FROM` to an address on that domain. Resend only sends. To *receive* mail at hello@unbrokenops.com, set up a mailbox provider (Google Workspace, Zoho, etc.) and add its MX records.

## Fidelity notes (vs. the approved design, `Main.dc.html`)

Compared side by side in Chrome at 1440px and 390px, full page, with animations off so both are caught in the same state, before the founder and footer changes below:
- **Layout:** every section has the same top and height as in the design at both widths.
- **Pixel difference:** 0.000% at 1440px. 0.012% at 390px, all of it the timeline label change below.

Intentional differences:
- **Footer:** replaced on request with the Class of One footer layout (brand, Explore, Policies, email box, line band, legal strip) in Unbroken's colours. The design's giant wordmark and "Building in stealth" chip are gone from it.
- **Founder card:** uses Rajat's photo, cropped round because it was supplied that way, and links to LinkedIn instead of the Netlify site.
- **The form is real.** The design's form only flipped to a thank-you. It now validates and stores.
- **Pages added:** Privacy and Terms are real pages (they were `#top` in the design), plus a styled 404. Nav and footer links point to `/#section`, so they work from every page. The jump menu shows only on the homepage.
- **Timeline labels below 1320px:** as designed, "Exception happens" and "Seen 3 days later" hang past the panel, which runs them off the screen at narrower widths, including 1280px laptops and phones. Below 1320px they now stay inside the panel. Above that, they match the design.
- **Section 06 in the nav:** the design's Talk section has no `data-sec`, so the jump bar could never reach "06 / 06" and stayed on Founder. It now does.
- **Jump menu:** also closes on Esc and on a click outside.
- **Anchors** land below the sticky nav. In the design, Observations and Talk scrolled their first line under it.
- **External links** (marked ↗) open in a new tab.
- **Problem task rows** are hidden before their animation only when JavaScript is on, so they read without it.

Kept as designed, worth a decision later:
- **Small mono labels** in the hero journey ("Requirement") and career chart ("NIIT Technologies"). The design's CSS appears to intend Archivo 15px and Geist 14.5px for these, but its runtime wraps values in a `<span>` that picks up the `.node span` and `.meta span` rules, so the design displays them small and mono. The site matches what the design displays. To get the larger type, remove the inner `<span>` in `Journey.tsx` and `Founder.tsx`.
